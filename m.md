# Portfolio Sync Tool — User Guide

Update Smartsheet with new project data from Monday.com.

---

## 1. Overview

The Portfolio Sync Tool is a custom Google Apps Script automation that bridges Monday.com and Smartsheet. It uses this Google Sheet as a hub to pull project data from Monday.com, stage it locally by region, and push new rows to Smartsheet.

### How it works

The sync runs in three steps for each enabled region:

| Step | What happens |
|------|-------------|
| **Extract** | The script pulls all project data from the region's Monday.com board via the API. |
| **Stage** | Results are written to a local staging sheet (one per region) so you can inspect exactly what was fetched. |
| **Sync** | The script compares staging data against Smartsheet by primary key (Item ID). Only projects that *don't already exist* in Smartsheet are added as new rows. Existing rows are never modified or overwritten. |

### What it does not do

- It does **not** update existing Smartsheet rows. If a project's data changes in Monday, those changes will not flow to Smartsheet automatically.
- It does **not** delete rows from Smartsheet. Removing a project from Monday has no effect on the Smartsheet side.

## 2. Running a sync

### Manual sync (recommended starting point)

1. Open the Google Sheet.
2. In the top menu bar, click **Portfolio Sync**.
3. Select **Run Full Sync**.
4. A toast notification appears in the bottom-right corner showing progress as each region is processed.
5. When complete, you'll see a final "Sync complete" toast.

The full sync typically takes under two minutes for the current data volume.

### Scheduled sync (optional)

If you want the sync to run on a schedule (e.g., daily at 3:00 AM):

1. Open the Apps Script editor: **Extensions → Apps Script**.
2. In the left sidebar, click the clock icon (**Triggers**).
3. Click **+ Add Trigger** in the bottom-right.
4. Configure:
   - Function: `runFullSync`
   - Event source: Time-driven
   - Type: Day timer
   - Time of day: Choose your preferred window
5. Click **Save**.

The trigger runs independently — you can still run manual syncs at any time.

## 3. Menu options

| Menu item | What it does |
|-----------|-------------|
| **Run Full Sync** | Runs the full Extract → Stage → Sync pipeline for every enabled target. |
| **Dry Run (Mock Payload)** | Prompts you for a region name, then builds the exact API payload the sync *would* send — without writing anything to Smartsheet. The result is written to a `._mock_` tab so you can review every row and cell value. Note: the dry run *reads from* both Monday and Smartsheet (to check what already exists), but it never *writes to* Smartsheet. |
| **Validate Configuration** | Checks that API keys are set, all referenced sheets exist, and every enabled target has the required fields. Results are shown in a pop-up and logged to the audit sheet. |

## 4. Workspace structure

### Control sheets

| Tab | Purpose |
|-----|---------|
| **Sync_Targets** | The control panel. Each row defines a sync target: its Monday board ID, local sheet name, Smartsheet ID, mapping sheet, and primary key column. Toggle the **Enabled** column to activate or deactivate a region. |
| **.audit_log** | Timestamped log of every sync run. Each entry includes the execution ID, the module that ran, a status (SUCCESS, INFO, WARN, or ERROR), and a message describing what happened. |
| **.table_mapping** | Developer reference describing the purpose and ownership of each tab in the workbook. |

### Data sheets

| Tab | Purpose |
|-----|---------|
| **Register (from Monday)** | Raw data dump from the Monday.com master register board. Populated by the script if the Register target has a Monday Board ID configured in Sync_Targets. |
| **.staging_NOAM** | Staging area for North America. Populated directly by the script from the NOAM Monday board. This is the data source for the NOAM Smartsheet push. |
| **.staging_EMEA/APAC** | Staging area for EMEA and APAC. Populated directly by the script from the EMEA/APAC Monday board. |

### Mapping sheets

| Tab | Purpose |
|-----|---------|
| **.header_map_NOAM** | Column crosswalk for North America. Row 1 contains Smartsheet column headers. Row 3 contains the corresponding Monday column headers. Columns marked `N/A` in either row are skipped. The script uses this crosswalk to resolve live Smartsheet column IDs via the API — you never need to enter column IDs manually. |
| **.header_map_EMEA** | Same structure as above, for the EMEA/APAC Smartsheet. |

### Mock / diagnostic sheets

| Tab | Purpose |
|-----|---------|
| **._mock_[region]** | Generated by the Dry Run. Shows every row and cell that would be sent to Smartsheet, including the primary key, project name, expected action (ADD or SKIP), the Smartsheet column name, and the sanitized value. |

## 5. Troubleshooting

If a sync fails or produces unexpected results, the `.audit_log` tab is your first stop.

### Reading the audit log

1. Open the `.audit_log` tab.
2. Filter the **Status** column by `ERROR` or `WARN`.
3. The **Module** column tells you which phase failed:
   - `Monday:[sheet]` — The Monday.com API call failed for that board.
   - `Smartsheet:[region]` — The Smartsheet push failed for that region.
   - `getSmartsheetMapping_` — The column mapping lookup failed.
4. The **Message** column contains the specific error (API response, missing sheet name, etc.).

### Common issues

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| "Missing MONDAY_API_KEY" | API key not configured | Add `MONDAY_API_KEY` in Script Properties (Apps Script → Project Settings → Script Properties). |
| "Mapping sheet not found" | The tab name in Sync_Targets doesn't match an actual sheet tab | Check spelling and case in the **Mapping Sheet** column of Sync_Targets. |
| "No usable mappings" | The mapping sheet exists but row 1 or row 3 is empty, or Smartsheet column names don't match | Open the mapping sheet and verify row 1 has Smartsheet headers and row 3 has Monday headers. Run Validate Configuration to confirm. |
| "Primary key header not found" | The staging sheet doesn't have the expected ID column | Check the **Source Primary Key Header** column in Sync_Targets. Default is "Item ID". |
| Rows not appearing in Smartsheet | The primary key already exists in Smartsheet (row is being skipped as expected) | Run a Dry Run — rows marked SKIP already exist. The sync is append-only. |
| HTTP 401 / 403 errors | API key expired or lacks permissions | Regenerate the key in Monday.com or Smartsheet and update Script Properties. |

### When in doubt

Run **Validate Configuration** first. It catches most setup issues before they reach the API.

## 6. Adding a new region

1. In **Sync_Targets**, add a new row with:
   - **Enabled**: TRUE
   - **Monday Board ID**: The board ID from your Monday.com URL.
   - **Region**: A label (e.g., "LATAM").
   - **Local Sheet Name**: Where Monday data will land (e.g., ".staging_LATAM"). The script creates this tab automatically.
   - **Smartsheet ID**: The sheet ID from the Smartsheet URL or properties panel.
   - **Mapping Sheet**: Name of a new mapping tab you'll create.
   - **Smartsheet Primary Key Column ID**: The column ID of the primary key column in Smartsheet (use the Smartsheet API or column properties panel to find this).
2. Create the mapping sheet tab. Copy an existing one (e.g., `.header_map_NOAM`) and update row 1 with the new Smartsheet's column headers and row 3 with the corresponding Monday column headers.
3. Run **Validate Configuration** to check for issues.
4. Run **Dry Run** for the new region to verify the payload looks correct.
5. Run **Full Sync**.
